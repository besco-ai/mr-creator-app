Permissões obrigatórias do token Cloudflare

Checklist para cada conta Cloudflare nova que entra no rodízio de domínios. Sem o item 1 desta lista o painel não consegue criar zona e o estoque de domínios trava por inteiro.

⚠️ A armadilha: existem DUAS permissões chamadas “Zone”

No formulário da Cloudflare aparece Zone dentro do grupo Account e Zone dentro do grupo Zone. Elas são coisas diferentes:

• Account → Zone → Edit = CRIA zonas novas — é essa que sempre esquecem.
• Zone → Zone → Edit = só mexe em zonas que já existem — não cria nada.

Se faltar a de Account, o painel devolve: Requires permission "com.cloudflare.api.account.zone.create" to create zones for the selected account

“Não acho Zone na lista do Account”

Ela existe — só está escondida no fim da lista. A lista é alfabética e Zone é o último item de todos, depois de Zero Trust, Zero Trust Resilience, Zero Trust: PII e Zero Trust: Seats. Quem para de rolar no “Zero Trust: Seats” acha que acabou.

Atalho: deixe Account selecionado na primeira coluna, clique no campo Select do meio e digite zone — o campo é de busca e filtra na hora. Escolha Zone e ponha o nível Edit.

1As 7 permissões do token

Crie em My Profile → API Tokens → Create Token → Create Custom Token. Nenhum template pronto serve (inclusive “Edit zone DNS”) — nenhum deles inclui a linha destacada.

#GrupoPermissãoNívelPara que o painel usa
1 Account Zone Edit Criar a zona do domínio (POST /zones). É a que costuma faltar.
2 Account Account Settings Read Listar a conta e casar o account_id (GET /accounts)
3 Account Cloudflare Pages Edit Criar / listar / apagar projeto e disparar deploy
4 Zone Zone Edit activation_check — acelera o status propagando
5 Zone Zone Read Ler zone_id e o status da zona
6 Zone Zone Settings Edit SSL Full + Always Use HTTPS
7 Zone DNS Edit Wildcard *.dominio A, apex A, MX do e-mail e TXT de verificação do Meta

2Escopo (Resources) — tão importante quanto as permissões

  • Account ResourcesInclude → a conta (ex.: Fulano@uorak.com's Account)
  • Zone ResourcesInclude → All zones from an account → a mesma conta
  • Client IP Address Filteringdeixar vazio
  • TTLsem data de expiração

Não escolha “Specific zone”

Zona criada depois do token nasce fora do escopo — o painel cria a zona e em seguida não consegue mais tocar no DNS dela. Tem que ser All zones from an account.

3Checklist antes de salvar o token

  • Marquei Account → Zone → Edit (a linha destacada)
  • Marquei Account → Account Settings → Read
  • Marquei Account → Cloudflare Pages → Edit
  • Marquei Zone → Zone → Edit e Zone → Zone → Read
  • Marquei Zone → Zone Settings → Edit
  • Marquei Zone → DNS → Edit
  • Zone Resources = All zones from an account (não “Specific zone”)
  • Sem filtro de IP e sem TTL
  • Colei o token no painel em admin → Cloudflare Dev junto com o Account ID (32 caracteres)

Editou um token que já existia?

O valor do token não muda ao editar permissões — não precisa recadastrar nada no painel. Já se você criar um token novo, tem que atualizar o valor em admin → Cloudflare Dev.

4Conferir se o token ficou certo

Sonda de leitura já instalada na VPS. Ela testa todas as contas cadastradas e diz OK/FALTA por permissão:

ssh root@2.25.147.134
php /root/gs_token_probe.php

Como ela testa a criação de zona: manda um nome inválido de propósito (probe--invalid--.invalidtld) e lê o erro que volta.

Resposta da CloudflareSignificado
1099 / 1049 — “unable to identify … as a registered domain”Permissão de criar zona OK (recusou o nome, não a permissão)
Requires permission "com.cloudflare.api.account.zone.create"Falta Account → Zone → Edit
1118 — “You have exceeded the limit for adding zones”Permissão OK, mas a conta está cheia de zonas pendentes → o painel marca zone_limit_reached=1 e passa para a próxima conta

Pegadinha do diagnóstico

GET /accounts responder success: true com a lista vazia não quer dizer que está tudo certo — é token sem Account Settings → Read. E o contrário também acontece: token que lista a conta direitinho e mesmo assim não cria zona. As duas permissões são independentes; teste sempre as duas.

5Por que isso trava o painel inteiro

A rotina domAbastecerPasso() trata os domínios em estoque_status='comprando' no passo 0 e retorna ali mesmo. Ou seja: um único domínio preso em “comprando” faz o cron de 2 minutos nunca chegar nos passos seguintes.

EstadoO que significaO que fica parado junto
comprandoDomínio pago, sem zona na Cloudflare— (é aqui que trava)
propagandoZona criada, esperando NS / SSL / MXNenhum domínio avança para ativo
ativoSite + certificado + e-mail prontosEstoque não repõe: nenhuma compra nova

Assim que um token do rodízio ganhar a permissão de criar zona, o cron destrava sozinho e processa a fila inteira. Para forçar na hora, adotando um domínio comprado fora do painel:

php /root/gs_adotar.php meudominio.net namecheap

O script cria a zona, aponta os NS no registrador, coloca em propagando e dispara o activation_check. Os 4 portões seguintes (zona active → NS delegados → wildcard + SSL → MX) o cron fecha sozinho.
